## 1. 시스템 개요

PokerMemo AI는 오프라인 토너먼트 포커 플레이어가 핸드 메모를 기록하면, Firebase에 저장된 누적 데이터를
Vertex AI/Gemini 기반 AI 에이전트가 분석하여 GTO/ICM 솔루션과 리크(약점) 분석 리포트를 자동 발행하는
Flutter 모바일 앱이다. Free/Plus/Pro 3단계 구독 티어로 운영되며, 결제는 Stripe 외부 링크로 처리한다.

## 3. 레이어 구조

Flutter(Dart) 앱 기준 폴더 구조 제안:

```
lib/
├── main.dart
├── core/                  # 공통 유틸, 테마(다크모드), 상수, 예외 처리
├── domain/                # 포커 도메인 모델 (핸드, 포지션, ICM, 핸드레인지 등)
├── services/              # Firebase/Vertex AI/Stripe 연동 서비스 레이어
├── providers/             # Provider/Riverpod 상태 관리 (UI와 철저히 분리)
└── screens/               # 화면별 UI 위젯 (메모 기록, 레인지 조회, ICM 계산기, 리포트 등)
```

- `providers/`(상태 관리)와 `screens/`(UI)는 서로 직접 참조하지 않고, 인터페이스를 통해서만 연결
- `domain/`은 포커 용어/수식을 다루므로 `agents/poker-agent.md` 글로서리 기준을 그대로 반영

## 4. 데이터 흐름

**(1) 핸드 메모 기록 → 핸드레인지/에퀴티 조회 (Free Tier)**
```
사용자 입력(핸드 상황) → Provider 상태 갱신 → Firestore에 메모 저장
→ 정적 핸드레인지/에퀴티 데이터 조회 → 화면에 결과 렌더링
```

**(2) 누적 데이터 기반 주간 리포트 자동 발행 (Pro Tier)**
```
Cloud Functions(스케줄 트리거) → Firestore에서 유저 누적 핸드 데이터 조회
→ Vertex AI/Gemini Flash 계열 API 호출 (리크 분석 + 리포트 생성)
→ 분석 시작 시간·판단 근거·토큰 수·결과 상태를 agent_execution_logs에 기록
→ 리포트를 Firestore에 저장 → 앱에서 사용자에게 알림/표시
```

**(3) Free→유료 전환 퍼널 자동화 (AI 운영 — XPRIZE "AI가 핵심 의사결정을 실행" 요건 대응)**
```
Cloud Functions(주기 트리거) → Firestore에서 Free 유저의 행동 패턴 조회
  (핸드 메모 건수, 핸드레인지/에퀴티 조회 횟수 등)
→ 규칙 기반 트리거로 Plus/Pro 전환 후보 선별
  (예: 메모 N건↑ + ICM 미사용 → Plus 후보 / 조회 M회↑ + 코칭 미경험 → Pro 후보)
→ Vertex AI/Gemini Flash로 유저별 개인화 전환 유도 메시지 생성
  (유저의 실제 기록을 근거로 한 맞춤 카피 + 가격 앵커링 문구 자동 삽입)
→ 트리거 감지 시각·판단 근거(행동 패턴)·생성 메시지·전환 결과를 agent_execution_logs에 기록
→ 1단계: AI 생성 → 개발자 검토 후 발송 / 2단계(베타 안정화 후): 신뢰도 높은 케이스부터 자동 발송
```
> 이 흐름은 "Free 모수 확보 → 유료 전환 입증"이라는 사업 우선순위를 실제로 구동하는 엔진이자,
> "AI가 비즈니스의 핵심 성장 동력을 운영하고 결과까지 추적 가능하다"는 XPRIZE 증빙 자료의 핵심이 된다.
> 자세한 설계 근거는 `docs/product-specs/business-strategy-proposal-v1.md` 5절 참조.

## 6. 비기능 요건 달성 전략

- **단순성/직관성**: Firebase 매니지드 서비스 위주로 구성해 인프라 직접 운영 부담 제거, 4계층 구조로 코드 추적 용이성 확보
- **AI 운영 증빙**: Cloud Functions에서 Vertex AI 호출 직후 `agent_execution_logs`에 자동 기록하는 공통 로깅 유틸리티를 P0에서 먼저 구축
- **다국어**: Flutter `intl` 패키지 + 로컬라이징 키 기반 영어/한국어 지원, 신규 화면 추가 시 키 누락 검수
- **보안**: Firebase Auth + Firestore 보안 규칙로 사용자 데이터 격리, 결제는 Stripe 외부 링크로 위임해 PCI 범위 최소화
- **정확성(도메인)**: `agents/poker-agent.md` 에이전트가 포지션 약어·ICM 변수명 등 도메인 데이터 구조를 검수

## 7. 보안 고려사항

- Firebase Authentication 기반 사용자 인증, Firestore 보안 규칙로 사용자별 데이터 접근 제어
- 결제는 Stripe 외부 결제 링크로 연결 — 카드 정보 등 민감 결제 데이터를 자체 서버/앱에 저장하지 않음
- 모든 외부 API 호출(Vertex AI, Stripe 등)에 try-catch 예외 처리 필수 (CLAUDE.md 행동 지침)
- API 키 등 민감 정보는 `.env` 및 Firebase 환경설정으로 관리, 절대 커밋 금지

## 8. 배포 구성

- Frontend: Flutter 빌드 → iOS App Store / Google Play Store 배포
- Backend: Firebase (Auth, Firestore, Cloud Functions) — Firebase 콘솔/CLI로 배포·관리
- AI: Google Cloud Vertex AI / Gemini Flash 계열 (기본값, 비용 효율 우선) — GCP 프로젝트 내 통합, 품질 부족 시 Pro 계열 부분 전환 검토
- 호스팅: Firebase Hosting (랜딩/대시보드 등 웹 자산 필요 시)
- 결제 증빙: Stripe 대시보드 (외부 연동, 별도 인프라 불필요)
