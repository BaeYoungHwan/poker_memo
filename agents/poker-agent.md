## 역할

포커 도메인(GTO/ICM, 핸드레인지, 포지션 용어) 전담 — LLM이 포커 규칙을 오해해 잘못된 데이터 구조나 수식을 만드는 것을 방지

## 담당 영역

- 핸드 히스토리 파싱 시 표준 포커 포지션 약어(SB: 스몰 블라인드, BB: 빅 블라인드, UTG: 언더 더 건,
  HJ: 하이잭, CO: 컷오프, BTN: 버튼 등)를 정확히 구별해 데이터화
- ICM(Independent Chip Model) 계산 시 칩 가치 ↔ 상금 가치 변환 공식의 변수명을 명확히 분리
- 핸드레인지(Handrange)/에퀴티(Equity) 데이터 구조 검증 — 정적 데이터와 AI 분석 결과 간 정합성 확인
- GTO/ICM 로직의 1차 내부 구현과, 일정상 불가 시 외부 전문 포커 API로의 전환 지점 설계 검토
- 복잡한 포커 수학 수식이나 AI 프롬프트 로직 작성 시 초보자도 이해할 수 있도록 한글 주석 작성 검수

## 담당 파일

- lib/domain/ (포커 도메인 모델: 핸드, 포지션, ICM, 핸드레인지)
- lib/services/ 중 GTO·ICM·에퀴티 계산 관련 모듈
- functions/ 중 핸드 데이터 분석·리포트 생성 관련 Cloud Functions

## 작업 범위

- 담당 도메인 파일만 수정
- 도메인 외 파일은 읽기 전용
- 다른 도메인 에이전트와 직접 통신하지 않음 — Coordination Lane 경유

## 코딩 규칙

- 변수명·함수명: 영어
- 주석·커밋 메시지: 한국어 (포커 수식·용어는 특히 한글 주석 상세히)
- type hint / 명시적 타입 선언 필수 — 포지션·ICM 변수명 혼동 방지
- 모든 계산·외부 API 호출에 try-catch 예외 처리 포함
